## During Development

### Micro-commit Strategy (Every 30-60 min)
```bash
# After each logical change
Claude: "Review my changes and suggest commit message"

# Or quick commits:
```

## Git Commands Cheat Sheet for Claude

### Understanding State
```bash
git status -sb                    # Brief status
git log --oneline -10            # Recent history
git diff                         # Unstaged changes
git diff --cached                # Staged changes
git branch -vv                   # Branch info
```

### Finding Information
```bash
git log --grep="pattern"         # Search commits
git log -S"code"                 # Find when code added
git blame <file>                 # Who changed what
git show <commit>                # Commit details
```

### Working with History
```bash
git reflog                       # Recovery tool
git bisect start                 # Find bug introduction
git cherry-pick <commit>         # Apply specific commit
```

## Best Practices

1. **Commit Early and Often**
   - Every logical change gets a commit
   - Easier for Claude to understand progress
   - Better for debugging later

2. **Meaningful Messages**
   - Follow the template format
   - Help Claude understand intent
   - Reference issues when applicable

3. **Branch Strategy**
   - One feature per branch
   - Include day number for hackathon context
   - Merge to main when feature complete

4. **Review Before Push**
   ```
   Claude: "Help me clean up commits with interactive rebase"
   Claude: "Review commit messages for clarity"
   ```
